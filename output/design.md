# Campus Customs 智能体工作台 · 设计说明（第 8 题）

前端代码在 `frontend/`（React + Vite + TypeScript），在该目录运行 `npm run dev` 后访问 `http://localhost:5173`。页面直接请求 `http://localhost:8000` 的 FastAPI 后端，所有工单、事件、余额和审批数据都来自后端接口，没有任何假数据；刷新页面后会从后端重新读取全部状态。

## 1. 页面布局及原因

页面采用**三栏工作台**，顶部是一条深蓝色店铺栏：

| 区域 | 内容 | 为什么这样放 |
|---|---|---|
| 顶栏 | 校徽式 “CC” 标志、店名、店铺今天（`desk.date_today`）、后端连接灯 | 每次操作前先确认“今天是哪天”和“后端是否在线”，这两件事决定所有判断是否可信 |
| 左栏 | 工单 101 / 102 / 103 卡片 | 工单是工作的入口，像收件箱一样固定在左边，随时切换 |
| 中栏 | 当前工单 → 五个智能体 → 实时工作过程 | 从上到下对应“要解决什么 → 谁在做 → 具体怎么做的”，阅读顺序和处理顺序一致 |
| 右栏 | 现金余额 → 待人工审批 → 演示数据重置 | 钱相关的内容集中在右边，和智能体的工作分开，强调“付款是人的决定” |

左右两栏在宽屏下固定在视口内并可单独滚动，中间的过程再长也不会把余额和批准按钮挤出屏幕。窗口小于 1240px 时右栏移到下方并排成卡片；小于 820px 时变成单栏，工单卡片自动换行，经检查在 375px、1024px、1280px 宽度下都没有横向溢出。

## 2. 五个智能体的视觉区分

每个智能体都有固定的**颜色 + 图标 + 角色标签**，在卡片、时间线、协作路线、审批申请里保持一致：

| 智能体 | 图标 | 颜色 | 角色标签 |
|---|---|---|---|
| 总负责人 | 🎓 | 学院金 `#b0812a` | 统筹决策 |
| 库存负责人 | 📦 | 青绿 `#1f7470` | 货架与补货 |
| 财务负责人 | 💰 | 墨绿 `#2f6f3e` | 现金与付款 |
| 场地负责人 | 🏛️ | 砖红 `#a64b2a` | 租约与店面 |
| 客服负责人 | 💬 | 紫 `#6c4a8a` | 客户草稿 |

人工审批人用深蓝 ✍️，系统事件用灰色 ⚙️，与五个智能体区分开。

## 3. 实时工作过程与各角色总结

- **智能体卡片**：顶部色条 + 圆形图标 + 状态（待命 / 工作中 / 已完成 / 本次未参与）。工作中的卡片会发光，并显示“正在：……”（最近一条对外事件）；完成后显示它交回的结论（`agent_finished`），并列出它委派了谁、用了哪些 MCP 工具。运行结束后从未被调用的角色明确标“本次未参与”，不编造内容；运行进行中尚未被委派的角色显示“待命”。
- **实时时间线**：运行中每 2 秒、空闲时每 6 秒向 `/api/events` 增量拉取。每条事件左侧是该智能体的颜色条，标出“发言 / 委派 / 工具 / 回复 / 完成 / 人工 / 系统”。委派和回复会把对方的名字用对方的颜色标出；工具调用默认折叠，展开后才看到参数和结果摘要，避免刷屏。被委派者的事件按委派深度缩进，一眼看出谁在为谁工作。
- **协作路线**：时间线顶部把所有委派串成一行，例如“🎓 总负责人 → 🏛️ 场地负责人、💰 财务负责人 → 🏛️ 场地负责人”，方便与第 6 题的预期计划对比。
- 只显示审计记录里的对外内容（发言、委派、工具、结果、人工操作），不显示模型内部思考。

## 4. 已解决工单、待审批申请和现金余额

- **工单状态**完全取自后端：`resolved` 显示绿色“✓ 已解决”；`waiting_approval` 显示琥珀色“⏳ 等待审批”；正在运行显示蓝色旋转的“◐ 运行中”；最近一次运行失败或中断显示红色“✕ 运行失败”，达到运行限制显示“⛔ 达到运行限制”；其余为“○ 未处理”。卡片左边框和当前工单顶部色条使用同样的颜色。等待审批、失败和达到限制都不会被显示成已解决。
- **启动按钮**在运行中、等待审批、已解决或重置中会被禁用，并说明原因；点击后立即进入“团队工作中…”状态，后端也会对重复运行返回 409。
- **待审批申请**以琥珀色卡片显示：工单号、收款方（大号字）、金额（最大号字）、类型和到期日、用途（智能体写的理由）、申请人（带颜色的智能体名）。必须先填写审批人姓名，点击“批准并支付 $X”后还要在确认框中再点一次“确认支付”。前端提交的金额和收款方只是给后端核对，真正的金额以服务器保存的申请为准。
- **现金余额**放在右上角深蓝卡片里，用大号衬线数字显示。批准成功后前端会重新调用 `/api/cash`，显示后端确认的真实余额，不会在前端自己减钱。有待审批申请时，卡片下方显示待审批合计和“若全部批准预计剩余”，预计为负时变红，并注明这只是预估。
- 批准失败（余额不足、金额不符、重复批准等）时，右下角提示框原样显示后端返回的原因，余额保持不变。

## 5. 让工作台更清楚、更好用的创意设计

1. **校园商店的视觉语言**：深蓝 + 米白的纸张底色、金色描边的校徽式标志、衬线体标题和金额，像一张店铺账本，同时保持界面干净。
2. **“总负责人的最终判断”卡片**：运行结束后把总负责人的结论单独放在工单下方，不必翻时间线就能知道结果和下一步。
3. **两步确认付款**：批准按钮上直接写出金额，确认框再完整复述“以谁的名义、向谁、付多少”，减少误点。
4. **审批人姓名记忆**：审批人姓名保存在浏览器本地，下次不用重填；当前选中的工单也会记住，刷新后回到原来的位置（业务状态仍然全部从后端读取）。
5. **清楚的异常提示**：后端未连接时顶栏变红并给出启动命令，页面自动重连；没有事件、正在加载、请求失败都有对应文字。
6. **演示数据重置**：右栏底部提供重置按钮，必须输入 `RESET` 才执行；有工单运行时自动禁用，方便第 9 题从原始数据重新开始完整运行。
